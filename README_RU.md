# SUB0 – Free Proxy Configuration Collector

[**🇺🇸 English**](README.md) | [**🇮🇷 فارسی**](README_FA.md) | [**🇨🇳 中文**](README_CN.md) | [**🇷🇺 Русский**](README_RU.md)

SUB0 — это автоматизированная система управления прокси-конфигурациями. Она собирает, проверяет, тестирует, обогащает и фильтрует конфигурации из различных источников. Проект использует параллельную обработку, многоэтапное тестирование соединений, геолокационные данные и механизмы фильтрации безопасности для создания конфигураций в различных форматах.

Каждый источник оценивается по четырем основным показателям:

- **Надежность (35%):** процент успешного получения и обновления конфигураций

Источники с оценкой ниже 30% автоматически отключаются в соответствии с логикой управления источниками проекта.

## ✨ Основные возможности

### Поддержка нескольких протоколов

- **VLESS** — легковесный прокси-протокол с поддержкой Reality и XTLS Vision
- **VMess** — прокси-протокол V2Ray
- **Trojan** — прокси-протокол на основе TLS
- **Shadowsocks** — зашифрованный прокси с поддержкой методов AEAD
- **Hysteria2** — высокопроизводительный прокси-протокол на основе UDP
- **WireGuard** — современный VPN-протокол; в текущей реализации присутствует только в исходном/тестовом текстовом выводе и по умолчанию отключен.
- **TUIC** — прокси-протокол на основе UDP; в настоящее время имеет ограничения, аналогичные WireGuard, и по умолчанию отключен.

### Продвинутый конвейер обработки

1. **Интеллектуальный сбор**
   - Поддержка Telegram-каналов, SSCONF-ссылок и пользовательских URL
   - Автоматическое декодирование Base64 и определение формата
   - Семантическое удаление дубликатов по протоколу, адресу, порту и учетным данным
   - Повторные запросы только при временных ошибках: тайм-ауты, проблемы соединения, HTTP 408, 429 и 5xx

2. **Географическое обогащение**
   - Автоматическое определение географического положения серверов
   - Маркировка флагами стран
   - Поддержка нескольких геолокационных API
   - Использование резервного механизма при недоступности основного API

3. **Распределение по странам**
   - Группировка конфигураций, прошедших тестирование Xray, по странам расположения серверов
   - Создание отдельных файлов подписок для стран, определенных в настройках
   - Повторное использование сохраненных географических данных для сокращения лишних API-запросов
   - Сохранение предыдущего файла страны, если в новом запуске для нее не найдено подходящих конфигураций

4. **Интеллектуальное переименование**
   - Создание описательных имен на основе характеристик протокола
   - Определение типа транспорта, например WS, GRPC и HTTP2
   - Определение параметров безопасности: TLS, Reality, XTLS и Vision
   - Добавление информации о порте и стране

5. **Многораундовое тестирование двумя ядрами**
   - Проверка соединений с помощью Xray Core и Sing-box Core
   - Несколько независимых раундов тестирования для каждого ядра
   - Сохранение конфигураций, успешно прошедших все заданные раунды
   - Чередование тестовых URL между раундами
   - Предварительная проверка доступности тестовых URL
   - Параллельная обработка с настраиваемым количеством Worker и Timeout

6. **Фильтрация безопасности**
   - Удаление небезопасных методов шифрования
   - Проверка настроек TLS/SSL
   - Фильтрация устаревших протоколов и параметров
   - Создание отдельных безопасных выходных файлов для поддерживаемых форматов

7. **Преобразование форматов**
   - Автоматическое создание конфигураций Sing-box JSON
   - Генерация конфигураций Xray с Load Balancing
   - Поддержка конфигураций Xray Fragment
   - Создание конфигураций Clash/Mihomo YAML
   - Поддержка Reality и XTLS Vision в поддерживаемых форматах вывода

### Для разработчиков

#### Fork и настройка

1. Создайте Fork этого репозитория.
2. Отредактируйте `settings/user_settings.py`, чтобы настроить:
   - URL источников и Telegram-каналы
   - Включенные протоколы
   - Параметры тестирования соединений
   - Приоритет геолокационных API
3. При необходимости отредактируйте `settings/fragment_settings.py` для настройки Fragment.
4. При необходимости измените словарь `TARGET_COUNTRIES` в `src/country_splitter.py`.
5. Включите GitHub Actions в своем Fork.
6. Процесс обновления будет выполняться согласно заданному расписанию.

## ⚙️ Параметры конфигурации

### `settings/user_settings.py`

Пример основных настроек:

```python
# Source URLs
SOURCE_URLS = [
    "https://t.me/s/your_channel",
    "https://raw.githubusercontent.com/user/repo/main/configs.txt",
]

# Power Mode
USE_MAXIMUM_POWER = True
SPECIFIC_CONFIG_COUNT = 0

# Protocol Filtering
ENABLED_PROTOCOLS = {
    "wireguard://": False,
    "hysteria2://": True,
    "vless://": True,
    "vmess://": True,
    "ss://": True,
    "trojan://": True,
    "tuic://": False,
}

# Config Age Filtering
MAX_CONFIG_AGE_DAYS = 1

# Xray Testing
ENABLE_XRAY_TESTER = True
XRAY_TESTER_MAX_WORKERS = 24
XRAY_TESTER_TIMEOUT_SECONDS = 5
XRAY_TESTER_ROUNDS = 3
XRAY_TESTER_BATCH_SIZE = 200

XRAY_TESTER_URLS = [
    "https://www.youtube.com/generate_204",
    "https://www.gstatic.com/generate_204",
    "https://cp.cloudflare.com",
]

# Sing-box Testing
ENABLE_SINGBOX_TESTER = True
SINGBOX_TESTER_MAX_WORKERS = 24
SINGBOX_TESTER_TIMEOUT_SECONDS = 5
SINGBOX_TESTER_ROUNDS = 3
SINGBOX_TESTER_BATCH_SIZE = 200

SINGBOX_TESTER_URLS = [
    "https://www.youtube.com/generate_204",
    "https://www.gstatic.com/generate_204",
    "https://cp.cloudflare.com",
]

# Geolocation APIs
LOCATION_APIS = [
    "api.iplocation.net",
    "freeipapi.com",
    "ip-api.com",
    "ipapi.co",
]
```

Отключение любого тестера пропускает соответствующий этап проверки соединений в текущем запуске. Файл предыдущего этапа передается дальше без изменений.

Обратите внимание: выходные файлы Sing-box, Clash и Xray Secure зависят от этапа тестирования Sing-box. Его отключение может снизить надежность этих выходных файлов.

### `settings/fragment_settings.py`

```python
FRAGMENT_ENABLED = True

FRAGMENT_STAGE_1 = {
    "packets": "tlshello",
    "lengths": ["5", "94", "1"],
    "delays": ["0"],
    "max_split": "0",
}

FRAGMENT_STAGE_2_ENABLED = True

FRAGMENT_STAGE_2 = {
    "packets": "1-1",
    "lengths": ["109", "1"],
    "delays": ["1"],
    "max_split": "355",
}

FRAGMENT_TLS_FINGERPRINT = "unsafe"
FRAGMENT_TLS_CIPHER_SUITES = "TLS_AES_256_GCM_SHA384:TLS_CHACHA20_POLY1305_SHA256:..."
```

Этот файл управляет двухэтапной фрагментацией TLS ClientHello для выходного файла `xray_fragment_loadbalanced_config.json`.

Здесь можно изменять параметры каждого этапа, TLS Fingerprint и Cipher Suites.

## 🔄 Автоматизация

Проект использует GitHub Actions для автоматического сбора и обновления конфигураций.

Основные возможности:

- Запуск по расписанию Cron, определенному в Workflow
- Ручной запуск через `workflow_dispatch`
- Автоматическое обновление выходных файлов
- Генерация графиков и отчетов производительности
- Создание сводки выполнения Pipeline

### Последовательность GitHub Actions

1. Получение конфигураций из всех источников
2. Обогащение географическими данными
3. Переименование конфигураций
4. Многораундовое тестирование с Xray Core
5. Разделение протестированных конфигураций по странам
6. Преобразование в формат Sing-box
7. Многораундовое тестирование с Sing-box Core
8. Фильтрация безопасности и создание безопасных выходных файлов
9. Генерация файлов Clash/Mihomo
10. Создание Xray Load Balanced конфигурации
11. Создание Xray Fragment конфигурации
12. Обновление графиков и отчетов
13. Формирование сводки Pipeline
14. Сохранение изменений в репозитории

## 🛡️ Безопасность

### Автоматическая фильтрация

Система фильтрует конфигурации на основе заданных правил безопасности, включая:

- Небезопасные методы шифрования Shadowsocks
- Устаревшие параметры VMess, например `alter_id`
- Конфигурации без необходимой криптографической защиты
- Некорректные настройки TLS, например `insecure=true`
- Конфигурации VMess с `security=none`

### Безопасные выходные файлы

Файлы Secure предназначены для хранения конфигураций, прошедших определенные проектом проверки безопасности.

Прохождение фильтров проекта не гарантирует абсолютную безопасность, анонимность или надежность стороннего поставщика услуг.

## 📊 Статистика и мониторинг

### Показатели производительности

Система может регистрировать следующие показатели для каждого источника:

- Общее количество полученных конфигураций
